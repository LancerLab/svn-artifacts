# IREE lane — provenance & re-derivation

This lane's recorded numbers live in `results/iree/*.jsonl` + `stats.json`.
They are **generated**, never hand-edited, from the raw artifacts produced by
the harness. To re-derive every number on a CUDA machine (driver ≥ sm_120):

```bash
# 1. install the pinned IREE + compose kernels from settings (idempotent)
benchmark2/iree/run.sh setup

# 2. run the full lifecycle and emit results/iree/*
benchmark2/iree/run.sh all            # minimal(E1) -> e2(small) -> e3 -> s12 -> semcheck -> oracle -> collect -> stats
benchmark2/iree/run.sh e2 --full      # full-size gate (recorded numbers)

# or, per stage:
#   run.sh minimal [--level2]   E1 mutants -> raw/mutants.jsonl
#   run.sh e2 [--full]          kernel gate -> raw/kernels.jsonl
#   run.sh e3                   remainder + expressibility
#   run.sh s12                  compute-sanitizer -> raw/sanitizer.jsonl
#   run.sh collect              raw/*.jsonl -> results/iree/*.jsonl
#   run.sh stats                -> results/iree/stats.json
```

`raw/` (compile logs, `.vmfb`, run logs) is intentionally gitignored — it is
regenerated by the commands above, so every committed number still traces to a
re-runnable raw artifact (manifest §8). Per-record `settings_hash` +
`kernel_hash` are carried on every record for QC traceability.
